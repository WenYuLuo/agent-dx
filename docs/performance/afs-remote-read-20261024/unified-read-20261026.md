# 统一异步远端读与24次固定对照

本交付把原生gRPC远端读收口为一个异步业务核心，删除用户同步/异步选择和重复同步原生读实现。应用调用不变；同步SDK接口只保留薄适配，本地磁盘及真正同步后端保留必要适配。已有CRC、文件级授权复用、缓冲复用与异常收尾继续保留。

## 一次请求怎么走

FUSE接收请求，dispatch接纳任务及同fh顺序票据；异步任务准备固定版本、授权与路由，等待Meta或远端时释放线程。无积压直接发请求，有积压只合并已经就绪且上下文兼容的范围，沿用一个返回流。A在共享磁盘额度内读入最终发送缓冲，释放磁盘额度后异步发送；B保留最终缓冲到ReplyData回复结束。票据跟随真实工作及子任务，取消等待不等于底层读已完成。

[配置、所有权和最小Rust编程范式](read-concurrency.md)给出完整说明。本次复用Tokio Future、任务、信号量和有界通道，没有新增通用线程池或公共调度库。

## 用户配置

原生gRPC读统一异步，没有`--dfs-read-async`或`[dfs_read_pipeline].enabled`选项。历史实验配置中的这些键应删除；旧enabled字段会被拒绝。应用不需要新增必填参数。

`fuse_workers`控制执行线程，`fuse_max_tasks`控制执行、排队及异步在途的已接纳任务数；省略后者时仍取workers×8。RPC、待发送请求、回复缓冲、A磁盘深度和超时分别限额，默认与范围见配置说明。没有新增自适应、预取策略、TLS关闭或libfuse修改。
