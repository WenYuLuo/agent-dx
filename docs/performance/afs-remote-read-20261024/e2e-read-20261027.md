# 远端读最终配置与限定E2E验收

当前候选保留完整业务读路径，落实回复缓冲默认256MiB可调、内核请求16MiB预读及自身挂载BDI接线；B端预取默认关闭，可显式启用。open授权仍需显式配置，既有默认开关不顺带改变。写CRC开启、原生gRPC读CRC默认off，receiver可选；默认可能交付正文静默损坏，这属于已接受的可靠性取舍。

cached路径使用内核预读和同版本缓存复用；direct只读长顺序流可使用有界B预取。256MiB回复额度下节点投机上限64MiB、每句柄最多16MiB，额度随真实工作和最后引用归还。大于1MiB的内部请求退出片段拼接，使用单个最终回复，避免持有源片段同时等待第二份完整缓冲。小跨边界读取保留复用。

## 业务边界

- close-to-open，不新增旧fd的完整正文/属性/mmap历史快照承诺。
- open到close授权复用，不增加中央即时撤销；已知本地失效仍拒绝。
- GC安全优先，允许延迟回收；长期容量治理另列。
- 有界排队，不新增严格优先级或远端冷小读时延SLA；内部资源相互等待不能豁免。
- 实际INIT与挂载BDI分开记录。权限不足/sysfs不可用记录失败并保留内核原限制，不把请求值称为已生效。

## 验证与结论

代码与上一轮已验证完整候选逐文件一致，复用其Linux库1671通过/39忽略、严格workspace/all-targets/all-features Clippy、fmt、release及限定FUSE门禁。PR95已由上游合并，本轮从最新主线接入后另提后续PR；主线集成门禁另行记录，不能称远端CI通过或已经合入。

固定225/225读取全部内容、EOF、资源及OOM检查通过。direct完整耗时中位947.354→646.621ms，五对均快且基线稳定，配对改善31.969%；RPC1024→283，每次正文/源读各1GiB，A显式复制0/B复制1GiB/读CRC扫描0。累计AFS CPU/GiB增加7.594%，超过原5%数值门槛；用适量CPU换取时延下降属于已认可的取舍，保留数值记录不等于认定优化无效。64KiB direct随机读配对慢4.197%且基线不稳定，其余不稳定及超线保留，不称整体性能准入。cached并发配对改善1.026%，混合耗时改善1.392%、内核热小读P99改善6%，相应门槛通过。

本轮E2E机器摘要见[e2e-read-20261027.json](e2e-read-20261027.json)。完整功能、压力、性能账本和失败原件保留于工作区证据目录，交付时附带最终报告。性能实验必须以本轮完整wall与稳定性结论为准，不累加旧批次收益；数值通过、稳定性通过、功能通过和产品准入分别列出。
